# recruiter-labs

Laravel 13 + Filament 5 (admin) · Inertia 2 + React 19 (React Compiler) · Tailwind 4 ·
TanStack Query only when needed · single monolith. Details: skill `project-core`.

## Hard rules

- **Language:** everything in the repo is English (code, comments, commits, PRs, docs, UI copy) unless a feature explicitly requires localization. No Portuguese in files.
- **Git:** never create branches, commit or push unless asked in that specific message. Applies to subagents too.
- **Testing:** never write or modify tests unless asked in that specific message (overrides Boost/`pest-testing` "test per change"; `code-reviewer` must not flag missing tests). Running existing tests is fine.
- **Inertia/React:** keep page files to page-level composition; reusable/substantial UI goes in `resources/js/components`. Small local components are arrow functions; the page itself is a default-exported function.
- **Docs:** only create docs when asked. `docs/features/<feature>/spec.md` (+ optional binding `tech-design.md`) is persistent and never auto-deleted; update it when reality diverges. Scratch plan `.md` files are deleted after execution. Execution state lives in `.claude/state/` (untracked).

## Delegation

For non-trivial work use the matching subagent (`laravel-backend`, `filament-admin`, `inertia-frontend`), run deterministic checks, then `code-reviewer` before finishing. Roles do only their given scope.

## Load on demand (skills in `.claude/skills/`)

| When | Skill |
| --- | --- |
| Lint / types / tests / format commands, token discipline | `project-core` |
| Executing a feature in `docs/features/` | `execute-feature` |
| Overview, Jobs, workspaces, Calendar, Kanban, pipeline, navigation, attention/progress | `recruitment-workflow` |
| `App\Ai\Agents`, criteria, evaluation, fit/coverage/confidence, interview brief, AI cache | `evaluation-integrity` |

Framework skills (Laravel, Filament, Inertia, Tailwind, Pest, Wayfinder, Fortify) are generated by Laravel Boost (`boost.json`) — don't hand-edit them. Use Boost MCP `search-docs` for version-specific docs.
